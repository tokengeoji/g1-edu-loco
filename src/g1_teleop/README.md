# G1-EDU 키보드 텔레옵

PC2의 통합 컨테이너 `jsj-g1-tools`에서 Unitree 고수준 보행기를 조작한다. Unitree의 모드 표에는 Walk Motion이 FSM 500, 허리 3자유도 보행이 501, Run이 801로 기재되어 있다. 같은 표는 29자유도 기체에서 `ai_sport` 8.6.x.x 이후 Run ID가 802로 바뀌었다고 설명한다. 연구실 기체에서 실제로 관측한 Run ID는 802다. 이 기체에서 500 전환으로 보행 문제가 해결된 기록은 없다. [Unitree 고수준 보행 서비스](https://support.unitree.com/home/en/G1_developer/sport_services_interface) · [연구실 Drive의 SDK 가이드](https://docs.google.com/document/d/19zWQ_dzpEi2x5Sw1CTLCrENBISpxnno_TCgQpMfb2ug/edit)

[컨테이너 생성·시작](../../README.md#pc2) · [IIC 실기체 운영 규칙](../../AGENTS.md)

처음 점검하는 날에는 [보행 전 점검 가이드](../../docs/teleop-preflight.md)에서 이미지 준비부터 모의 정지까지 순서대로 확인한다.

## 실행

`jsj-g1-tools`가 실행 중인 G1-EDU PC2에서 SSH 터미널 두 개를 사용한다. 첫 번째 터미널은 온도·배터리 모니터용, 두 번째 터미널은 키보드 조작용이다. 두 터미널 모두 같은 컨테이너에 접속한다.

**G1 호스트 · 터미널 1**

```bash
docker exec -it jsj-g1-tools bash
```

**컨테이너 내부 · 터미널 1**

```bash
g1 interfaces
g1 health eth0
```

`eth0`는 예시다. 실제 G1 연결용 유선 NIC 이름으로 바꾸고, 모터 온도와 배터리 데이터가 새로 들어오는지 확인한다. 조작하는 동안 모니터를 켜 둔다.

**G1 호스트 · 터미널 2**

```bash
docker exec -it jsj-g1-tools bash
```

### 연구실에서 실기체 상태와 키 입력 확인

| 실행 모드 | 확인할 수 있는 것 |
| --- | --- |
| `--preview --interface eth0 --domain 0` | 시작할 때 실제 FSM과 29개 관절의 위치·속도를 읽고, 관측한 FSM에서 키 입력을 모의 실행한다. 로봇 NIC가 필요하다. |
| `--dry-run` | 기체와 통신하지 않고 모의 FSM 802에서 키를 직접 연습한다. 기본 실행 모드다. |
| `--status --interface eth0 --domain 0` | 실제 FSM ID와 응답한 서비스, 서비스 API 버전, `GetFsmMode`의 정적·동적 상태를 표시하고 종료한다. |
| `--feedback --interface eth0 --domain 0` | G1이 추정한 평면 위치, 속력, 회전속도를 0.25초마다 별도 터미널에 표시한다. 조종기와 SDK 조작을 같은 기준으로 비교할 수 있다. |
| `--live --interface eth0 --domain 0` | 입력한 모드·이동·정지 명령을 실제 기체로 전송한다. 별도 세션에서 명시적으로 실행한다. |

**컨테이너 내부 · 터미널 2 · 상태 수신 후 모의 키 입력**

```bash
g1 teleop --preview --interface eth0 --domain 0
```

1. 모니터와 같은 NIC를 지정한다. 시작 시 Unitree SDK의 `GetFsmId` 응답과 `rt/lowstate` 한 샘플을 읽는다. `[시작 시점 실측]`에는 실제 FSM, 29개 관절의 위치·속도가 모두 유효하다는 `q/dq 수신 29/29`, 왼쪽 무릎(`left_knee`)의 `q`(rad)와 `dq`(rad/s)가 표시된다. FSM 조회, 새 샘플 수신 또는 관절값 검사가 실패하면 진단 메시지를 출력하고 키 입력 전에 종료한다.
2. 시작값이 0 또는 4라면 `2` → 4초 안에 `Enter`로 메뉴에 표시된 모의 Run을 선택한다. 이미 801 또는 802이면 바로 `i`로 전진 요청(기본 0.30 m/s)을 확인한다. `f`는 현재 세션의 FSM을 읽는다.
3. `k`를 누르면 속도 0을 요청하고 조작을 계속한다. `Ctrl+C`를 누르면 정지 요청 후 셸로 돌아온다. 미리보기에서 모드 전환·속도·정지는 메모리에서 처리된다.

### 자동 회귀 검사

다음 명령은 모의 데이터를 사용해 키 처리, 터미널 입력, 미리보기의 상태 수신 경로를 자동 검사한다. 수동 키 입력과 로봇 연결은 필요 없다. 통합 도구 이미지 빌드 때도 제어·미리보기·상태 진단 검사가 자동 실행되며 실패하면 이미지 빌드가 중단된다.

**컨테이너 내부 · 자동 검사를 다시 실행할 때**

```bash
python3 -m unittest g1_teleop.test_control g1_teleop.test_terminal g1_teleop.test_preview g1_teleop.test_status g1_teleop.test_feedback g1_teleop.test_services
```

### 실제 기체 조작

첫 실기체 동작은 숙련자 입회하에 기체 지지, 물리 조종기, 모터·배터리 상태를 확인하고 진행한다. FSM 802에서는 내장 보행기가 팔을 흔들 수 있다. 팔 고정이 필요한 실험은 아래 실기체 조작을 시작하기 전에 이 제약을 확인한다. 같은 컨테이너에서 실기체 텔레옵은 한 세션만 실행한다.

**컨테이너 내부 · 터미널 2 · 실기체에 명령을 보낼 때**

```bash
g1 teleop --live --interface eth0 --domain 0
```

시작 화면의 `[실기체]` 표시를 확인한다. 일반 보행을 선택하려면 기체의 전환 조건을 확인한 뒤 `v`와 `Enter`로 FSM 500을 요청한다. `f`에서 500이 확인되면 다음 방향 키부터 속도를 요청할 수 있다. Run 모드는 `2`와 `Enter`로 요청한다. `k` 또는 스페이스로 속도 0을 요청한다.

## 이동과 속도

기본 조작은 ROS 2 `teleop_twist_keyboard`의 평면 키 배치다. PC2의 텔레옵은 이동 키를 Unitree `LocoClient.Move(vx, vy, yaw)` 호출로, 정지 키를 `StopMove()` 호출로 바꾼다. SDK는 두 함수 안에서 API 7105에 `velocity=[전방, 좌측, 좌회전]`과 초 단위 유효시간을 보낸다. [ROS 2 키 배치](https://github.com/ros2/teleop_twist_keyboard) · [공식 Move·StopMove 구현](https://github.com/unitreerobotics/unitree_sdk2_python/blob/814556d15970dd2ecf1c9984e845ca02ab07e206/unitree_sdk2py/g1/loco/g1_loco_client.py#L140-L153)

| 키 | 기체 기준 요청 |
| --- | --- |
| `i` / `,` 또는 `↑` / `↓` | 순수 전진 / 후진. 초기 배율 1배에서 `vx=+0.30 / −0.30` m/s, `vy=yaw=0` |
| 소문자 `j` 또는 `←` / 소문자 `l` 또는 `→` | 제자리 좌회전 / 제자리 우회전. `vx=vy=0`, 기본 `yaw=+0.30 / −0.30` rad/s |
| `u` / `o` | 전진하며 좌회전 / 우회전 |
| `m` / `.` | 후진하며 우회전 / 좌회전. 초기 배율에서 `vx=−0.15` m/s, `vy=0`, `yaw=−0.30 / +0.30` rad/s |
| `Shift+j` (대문자 `J`) / `Shift+l` (대문자 `L`) | 왼쪽 / 오른쪽 옆걸음. `vx=yaw=0`, 기본 `vy=+0.10 / −0.10` m/s |
| `U` / `O` / `M` / `>` | 전진 좌측 / 전진 우측 / 후진 좌측 / 후진 우측 대각선 이동. 회전속도 0 |
| `q/z` · `w/x` · `e/c` | 다음 이동의 선속도와 회전속도 · 선속도만 · 회전속도만 각각 10% 증가/감소. 배율은 0.5~2배이며 순수 전후진은 최대 0.30 m/s |
| `+` / `-` | 다음 이동의 선속도·회전속도 배율을 함께 0.25씩 증가 / 감소 |
| `!` / `@` / `#` / `$` | Run(801/802)의 SDK 속도 상한 단계를 0 / 1 / 2 / 3으로 선택 |
| `k` 또는 스페이스 / `Ctrl+C` | 속도 0 요청 후 조작 계속 / 최종 속도 0 요청의 결과를 표시하고 종료 |
| `f` / `?` | 현재 세션의 FSM / 전체 모드·키 안내 |

11월 23일 두 실험에 기록된 모든 속도 요청의 `vy`는 0이었다. 두 번째 실험에서 소문자 `l`에 해당하는 회전 요청 구간의 추정 방위 변화는 약 −1.69°였다. 두 실험에서는 대문자 `J/L`의 실기체 옆걸음을 시험하지 않았다. 서비스의 수락 응답은 요청 처리를 뜻하며, 실제 옆걸음은 기체 좌측 변위와 현장 관찰로 확인한다.

| 전송 방식 | 방향 키를 한 번 누를 때 | 같은 키를 길게 누를 때 |
| --- | --- | --- |
| 기본 `Move` | 현재 FSM을 확인한 뒤 한 번 전송한다. SDK 유효시간은 호출 시점부터 1초다. | 터미널에서 새로 받은 반복 입력으로만 같은 방향을 최대 10 Hz로 전송한다. |
| `--timed-velocity` | 마지막 입력부터 1초간 타이머로 `SetVelocity`를 최대 10 Hz로 반복한다. 각 호출의 `duration`은 입력 기한까지 남은 시간이다. | 새 반복 입력이 도착할 때마다 입력 기한을 갱신한다. |

두 방식 모두 마지막 이동 입력에서 1초가 지나면 텔레옵이 속도 0을 요청한다. 처리 중인 RPC가 지연되면 정지 요청 전송도 늦어질 수 있다. 즉시 정지를 요청하려면 `k` 또는 스페이스를 누른다. `Ctrl+C`는 최종 정지 요청의 7105 응답을 확인하고 종료한다. 통신 오류로 정지 응답을 확인하지 못하면 오류를 표시하고 실패 상태로 종료한다. 실제 정지는 현장에서 확인한다. 반복 입력이 들어왔는지는 정지 출력의 이동 입력 횟수로 확인할 수 있다.

## 텔레옵에서 모드 변경

프로그램을 열면 화면에 숫자 키와 일반 보행 키 `v`가 이름과 함께 표시된다. 키 번호와 기체가 보고하는 FSM ID는 서로 다르다. 예를 들어 1번은 FSM 4, 2번은 메뉴에 표시된 Run ID다. 4/5번은 보행 설정값을 바꾼다. 원하는 키를 한 번 누른 뒤 선택 내용이 표시되면 4초 안에 `Enter`를 누른다. `Esc`로 취소할 수 있다. 요청 뒤 화면에 표시되는 실제 FSM과 기체 자세를 확인한다.

| 키 → Enter | SDK에 요청하는 모드 |
| --- | --- |
| `v` | 일반 보행(Walk Motion). 고정 버전의 SDK `Start()`와 같은 `SetFsmId(500)`을 호출해 반환 코드를 검사한다. [Unitree SDK](https://github.com/unitreerobotics/unitree_sdk2_python/blob/814556d15970dd2ecf1c9984e845ca02ab07e206/unitree_sdk2py/g1/loco/g1_loco_client.py#L120-L154) |
| `2` | Run 모드. 시작 시 801 또는 802를 관측하면 해당 ID를 사용하고, 다른 상태에서 시작하면 연구실에서 관측한 802를 기본값으로 사용한다. 기체의 Run ID를 알고 있으면 `--run-fsm 801` 또는 `--run-fsm 802`로 2번 키의 대상을 지정할 수 있다. |
| `8` | 허리 3자유도 보행(501). 해당 모델을 확인하고 실행 옵션 `--waist-3dof`를 지정한 경우 |
| `1` / `3` | 잠금 기립(4) / 위치 제어 쪼그림(2). 균형 제어가 없어 기체 지지 필요 |
| `6` | 균형 쪼그림과 기립 간 전환(706). 전환 후 현재 자세를 직접 확인 |
| `7` 또는 `9` | 의자에 앉기(3). 의자 위치와 기체 지지 확인 |
| `0` | 댐핑(1). 기체가 자세를 유지하지 못하므로 지지 확인 |
| `4` / `5` | 500/501에서 조작자가 `Enter`로 확인하면 `SetBalanceMode(0/1)`을 요청한다. 안정 시 제자리걸음 해제 / 속도 0에서도 계속 제자리걸음. 802의 첫걸음에는 적용하지 않는다. |

**802에서의 팔 동작.** 텔레옵은 팔 관절, 제스처, 저수준 명령을 보내지 않는다. 내장 보행기가 팔을 흔들 수 있으며 802에서 양팔을 고정하는 공식 기능은 확인되지 않았다. Unitree의 XR 상체 제어 예제는 보행과 병행할 수 있는 모드를 Regular로 명시한다. [Unitree XR 지원 모드](https://github.com/unitreerobotics/xr_teleoperate#32-parameter-description)

## 모드는 바뀌지만 걷지 않을 때

| 현장에서 보이는 출력 | 의미와 확인 순서 |
| --- | --- |
| `[모의]` | `--preview`에서는 시작 상태만 실측하며, 이후 `f`·이동·정지 출력은 모의 실행이다. `--live` 세션은 `[실기체]`로 표시된다. |
| `[실기체]`에서 `i`를 눌렀는데 현재 FSM이나 전환 미확인 메시지만 표시 | `f`로 실제 모드를 본다. 예를 들어 일반 보행을 요청한 뒤 실제 값이 계속 802라면 화면에 ‘요청한 FSM 500 진입 미확인’이 표시되고 이동 입력을 차단한다. 이 기체에서는 과거에도 500 전환이 되지 않았다는 기록이 있다. |
| 7105의 RPC 오류 또는 상태 조회 오류 | 속도 요청이 거절됐거나 응답을 확인하지 못한 경우다. `k`로 정지하고 오류 코드, 서비스, FSM을 기록한다. |
| `Move(7105) 수락` 또는 `SetVelocity(7105) 수락`인데 발걸음 없음 | 보행 서비스가 7105에 코드 0을 반환했다. 정지한 뒤 읽기 전용 상태와 기체 소프트웨어 버전을 기록한다. |
| 구버전에서 키 입력이 곧바로 만료됨 | 0.25초 기한을 쓰던 버전은 격리한 DDS 서버의 조회 응답이 0.30초 늦어지자 전진을 전송하지 않았다. 이후 남은 시간을 전송하는 방식에서는 같은 조건에서 약 0.69초의 전진 요청이 관측됐다. 현재 기본 `Move`는 입력 기한 내에 FSM을 확인한 뒤 1초짜리 요청을 보낸다. |

### FSM 802에서 나타난 전후진 무반응

2026년 11월 23일, 운영자는 같은 연구실 기체의 FSM 802에서 순정 조종기로 회전 없이 앞뒤로 걸었다고 확인했다. 키보드에서는 `eth0`, DDS 도메인 0, `sport` 서비스로 순수 전후진 ±0.15 m/s를 두 차례 시험했으며, 두 번 모두 현장에서 제자리에 머무는 것을 확인했다. 이전 현장 출력에서도 +0.165 m/s 전진 요청이 수락된 뒤 제자리였다. 키 유효시간 안에 속도 요청을 반복 전송하도록 수정한 뒤에도 ±0.15 m/s에서 증상이 재현됐다.

두 시험 모두 당시의 `SetVelocity` 경로를 사용했다. 특히 2차 시험은 타이머 재전송과 남은 유효시간이 적용된 기록이다. 현재 기본 `Move`와 `StopMove`도 내부적으로 7105를 호출하고, 텔레옵은 내부 호출의 반환 코드를 확인한다. 기존 2차 시험과 같은 전송 방식을 선택하는 옵션은 `--timed-velocity`다. [공식 SetVelocity 구현](https://github.com/unitreerobotics/unitree_sdk2_python/blob/814556d15970dd2ecf1c9984e845ca02ab07e206/unitree_sdk2py/g1/loco/g1_loco_client.py#L70-L78)

다음은 갱신을 적용한 2차 시험(11:26–11:29 KST)에서 요청·응답과 관절 센서, 오도메트리를 같은 시간 구간으로 맞춘 결과다. 전방 변위는 각 구간이 시작됐을 때 기체가 바라보던 방향으로 환산한 추정값이다.

| 키 | 요청한 `[vx, vy, omega]` | 관측 요청 / 성공 응답 | 다리 관절 최대 실측 변화폭 | 구간별 전방 변위 |
| --- | --- | ---: | ---: | --- |
| `i` 전진 | `[+0.15, 0, 0]` | 13 / 12 | 0.0093° | 두 구간 모두 0.0 cm |
| `,` 후진 | `[-0.15, 0, 0]` | 7 / 5 | 0.0117° | 0.0 cm |
| `o` 전진하며 우회전 | `[+0.15, 0, -0.30]` | 2 / 2 | 24.69° | +8.4 cm |
| `.` 후진하며 좌회전 | `[-0.15, 0, +0.30]` | 18 / 17 | 7.69° | −6.5 cm, −3.5 cm |

2차 시험의 전진(`i`, W1)과 전진 우회전(`o`, W4)은 요청 직전 0.4초간 골반 피치 중앙값이 각각 1.005°와 1.004°였다. 전진 때는 다리 관절의 최대 실측 변화폭이 0.0049°였고 보행기는 정적 상태에 머물렀다. 전진 우회전 때는 요청 26 ms 뒤 첫 동적 상태가 관측됐고 관절 변화폭은 24.69°였다.

순수 전후진 세 구간에서 채집한 FSM 표본 25개는 모두 802의 정적 상태(`fsm_mode=0`)였다. 다리 목표각의 최대 변화폭도 0.89°에 그쳤다. 직진과 같은 전진 속도에 회전을 더한 `o` 구간에서는 FSM 표본 9개 모두 동적 상태(`fsm_mode=1`)였고 다리 목표각은 최대 49.94° 변했다. 순수 전후진 요청 20건 중 17건에 성공 코드 0이 돌아왔고 나머지 3건은 기록기에서 응답을 짝짓지 못했다.

두 시험을 합치면 순수 전후진 여섯 구간에서 7105 요청 31건 중 27건에 성공 응답을 대응시켰다. 해당 구간의 FSM 표본 77개가 모두 `802 / fsm_mode=0`이었고, 12개 다리 관절 중 가장 큰 실측각 변화폭은 0.020°였다. 2차 시험에서는 세 구간 전후 0.5초를 포함해 오도메트리의 x·y가 일정했다. 1차 시험의 오도메트리 기록은 직진 구간 이후에 시작됐다. 키 이름은 수신한 속도 벡터를 기준으로 대응시켰다. 물리 키를 누른 시각, 펌웨어의 보행 개시 판단과 지면 접촉력은 이 기록에 없다.

두 시험에서는 **±0.15 m/s의 순수 전후진 요청을 수락한 뒤에도 보행기가 정적 상태에 머물렀다.** Unitree는 Run의 최대 속도 단계를 문서화했지만 802에서 순수 전후진이나 회전이 시작되는 최소 속도는 제시하지 않는다. 이 기록으로는 보행기의 내부 판단이나 전류·온도 제한 작동 여부를 판별할 수 없다. [Unitree 보행 서비스](https://support.unitree.com/home/en/G1_developer/sport_services_interface) · [실험 원본과 CSV](https://app.notion.com/p/4213c6661b7d81a1b10befc9f97c7a68)

이후 운영자는 +0.30 m/s에서 실제 전진을 관찰했고 정지 상태에서 첫걸음을 떼기 어렵다고 보고했다. `i`와 함께 소문자 `m`(후진 우회전)과 `,`(순수 후진)도 눌렀다. 각 키를 눌렀을 때의 시작 자세와 개별 결과를 구분한 새 요청·관절·오도메트리 원본은 없어 순수 후진 −0.30 m/s의 결과는 별도 확인이 필요하다.

### FSM 802 전후진의 기본 속도와 고정 속도

속도 옵션 없이 기본 배율에서 `i`를 누르면 공식 예제와 같은 `Move(0.3, 0, 0)`, `,`는 `Move(-0.3, 0, 0)`을 호출한다. 기본 순수 전후진은 `x` 한 번으로 0.27 m/s로 낮아지고, 배율을 높여도 0.30 m/s를 넘지 않는다. `--straight-speed 0.30`을 명시하면 배율을 바꿔도 순수 전후진 크기가 0.30 m/s로 고정된다. 옆걸음은 기본 0.10 m/s이며, `m`의 후진 선회는 1배에서 `Move(-0.15, 0, -0.3)`이다. [공식 전진 예제](https://github.com/unitreerobotics/unitree_sdk2_python/blob/814556d15970dd2ecf1c9984e845ca02ab07e206/example/g1/high_level/g1_loco_client_example.py#L90-L98)

**컨테이너 내부 · 기체에 명령을 보내기 전 전진·후진의 부호 확인**

```bash
g1 teleop --dry-run
```

`i` → `k` → `,` → `k` 순서로 전진·후진의 `vx`가 각각 +0.300과 −0.300이고 `vy`와 `yaw`가 모두 0인지 확인한다. 만료·정지 키·종료는 기본 경로에서 `StopMove()`를 호출한다.

**G1 호스트 · 오도메트리를 읽을 세 번째 SSH 터미널 열기**

```bash
docker exec -it jsj-g1-tools bash
```

**컨테이너 내부 · 터미널 3 · 정지 상태에서 각 방향 시험 전에 실행**

```bash
g1 teleop --feedback --interface eth0 --domain 0
```

공식 `rt/odommodestate`의 새 샘플이 표시되는지 확인한다. 시작 전방 Δ는 첫 샘플의 방위를 기준으로 한 변위다. 전진은 양수, 후진은 음수다. 각 방향에서 정지 중의 변동폭, 시험 중 발걸음, 전방 Δ, 좌측 Δ, 방위 변화를 함께 기록한다. 다음 방향을 시험하기 전 정지 상태에서 이 구독을 종료한 뒤 다시 시작하면 기준점이 재설정된다. [Unitree G1 오도메트리](https://support.unitree.com/home/en/G1_developer/odometer_service_interface)

첫걸음 구간을 분석하려면 별도 터미널에서 `g1 monitor record --with-teleop --run start-01 --nic eth0 --domain 0 --seconds 20`을 실행한다. 기록기는 기체에 명령을 보내지 않는다. 실행 폴더의 `state/teleop.jsonl`에 기록된 속도 요청과 보행 상태 변화의 수신 시각을 `state/samples.jsonl`의 기체 IMU·다리 관절 표본과 대조할 수 있다.

**컨테이너 내부 · 터미널 2 · 현장 점검 후 승인한 평지 시험**

```bash
g1 teleop --status --interface eth0 --domain 0
g1 teleop --live --interface eth0 --domain 0
```

1. `--status`에서 응답 서비스, FSM, 서비스 API 버전을 기록한다. 기체 소프트웨어와 `ai_sport` 버전은 Unitree 앱에서 별도로 확인한다. `--live`에서 `f`로 실제 FSM을 읽는다. 802 전환이 필요하면 메뉴에 2번의 대상이 802인지 확인한다. 대상이 801이면 `--run-fsm 802`를 명시해 다시 시작한다. 현장 전환 조건을 확인하고 `2` → `Enter`로 요청한 뒤 `f`로 다시 읽는다.
2. 같은 평지와 지지 조건에서 `i`를 시험한 뒤 `k`로 정지한다. 이어서 정지 상태에서 별도 구간으로 `,`를 같은 시간 동안 시험하고 `k`로 정지한다. 키 입력 방식과 전송 옵션도 함께 기록한다. `Ctrl+C`는 속도 0을 요청하고 종료한다. 화면의 정지 응답과 현장의 정지를 모두 확인한다.
3. 각 방향의 발걸음과 오도메트리를 확인하고 아래 기준으로 결과를 기록한다.

| ±0.30 m/s의 현장 결과 | 해석과 기록 |
| --- | --- |
| 양방향에서 발걸음과 같은 부호의 전방 Δ가 확인됨 | 해당 전송 방식과 속도에서 양방향 이동을 확인한 값으로 기록한다. 이전 시험과 속도·유효시간이 함께 달라지면 어느 변경이 영향을 주었는지 구분할 수 없다. |
| 한 방향만 반응 | 전·후진을 따로 기록한다. 실패 방향의 요청 부호·성공 응답, FSM, 다리 관절, 전방 Δ를 성공 방향과 대조한다. |
| 양방향 모두 성공 응답 후에도 제자리 | 속도 크기를 바꿔도 증상이 지속된 경우다. `--status`, 앱 버전, 실제 속도 벡터·유효시간, 관절·오도메트리 기록, 정상 조종기 결과를 묶어 Unitree에 해당 버전의 802 보행 개시 조건을 문의한다. |
| 응답 또는 오도메트리 누락 | 어느 관측이 누락됐는지 기록한다. NIC·도메인·서비스와 새 샘플 수신을 확인한 뒤 변위를 판정한다. |

**컨테이너 내부 · 읽기 전용 상태와 기체 형식 조회**

```bash
g1 teleop --status --interface eth0 --domain 0
g1 monitor probe --nic eth0 --domain 0 | grep -oE '"mode_machine": *[0-9]+'
```

`mode_machine`은 기체 형식이며, [Unitree의 공식 모델 표](https://github.com/unitreerobotics/unitree_ros/blob/master/robots/g1_description/README.md)에서 허리 구성과 대조할 수 있다. 허리 고정구의 실제 장착 상태와 앱의 허리 잠금 설정도 확인한다. Unitree 앱의 기체 소프트웨어·ai_sport 버전을 기록한다.

`GetFsmId`는 선택된 FSM, `GetFsmMode`는 제어기가 보고한 정적(0)·동적(1) 상태다. `GetServerApiVersion`은 서비스 API 버전이며 기체 소프트웨어 버전은 Unitree 앱에서 확인한다. 속도 요청 수락과 정적·동적 값만으로 실제 변위를 판정할 수 없다. 필요한 경우 [상태 모니터](../g1stairs/monitoring/README.md)에서 실험 중 관절 `q/dq`를 기록해 현장 관찰과 대조한다.

FSM 501은 허리 3자유도 보행용이다. 연구실 Drive의 사용자 매뉴얼 43~45쪽에 따르면 허리 3자유도 사용 조건은 허리 고정구가 제거되어 있고 Explore 앱의 허리 모터가 잠금 해제된 상태다. 텔레옵은 이 구성을 확인한 조작자가 `--waist-3dof`를 지정한 경우에만 501을 허용한다.
